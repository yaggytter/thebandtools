## 1. 全体像

```
                ┌────────────────────────────┐
                │  周波数ナレッジベース (KB)   │  ← 帯域・楽器・声・EQ のデータ
                │  bands / sources / tips     │
                └──────┬───────┬───────┬─────┘
                       │       │       │  「この周波数って何？」を全画面で同じカードで表示
     ┌─────────────────┘       │       └──────────────────┐
┌────▼──────┐        ┌─────────▼────────┐        ┌────────▼────────┐
│アナライザー│        │ ハウリングチェック │        │  学ぶ（周波数マップ│
│タップ→カード│        │ 結果→カード/EQ提案│        │  /解説/クイズ）    │
└────┬──────┘        └─────────┬────────┘        └────────┬────────┘
     └──────────────┬──────────┴───────────────┬──────────┘
              ┌─────▼──────┐             ┌─────▼──────┐
              │ DSPコア     │             │ 学習履歴    │
              │ FFT/検出/音源│             │ (IndexedDB) │
              └────────────┘             └────────────┘
```

**連動のルール**: 画面上に周波数（Hz）が表示される場所はすべてタップ可能にし、同じ「周波数カード」を開く。
カードには「その帯域の呼び名・聞こえ方・そこにいる楽器/声・削る/持ち上げると何が起きるか・試聴ボタン」が並ぶ。
これにより、ハウリングチェックを使うたびに自然と周波数の知識が積み上がる。

## 2. 周波数ナレッジベース（学習コンテンツの中核）

### 2.1 帯域の定義（初版案）

| ID | 帯域 | 呼び名 | 聞こえ方・特徴 | 主にいる音 | 多すぎると | 少なすぎると | ハウリング傾向 |
|---|---|---|---|---|---|---|---|
| sub | 20–60Hz | 超低域 | 耳より体で感じる振動 | キックの胴鳴り、ベース5弦Low B(31Hz)・4弦E(41Hz) | ステージが濁る・風/振動ノイズ | 迫力が出ない | 歌マイクでは不要→HPFで切る。内蔵マイクでは測定不可 |
| bass | 60–150Hz | 低域（ボトム） | 「ドン」「ブーン」太さ・重さ | キック(60–100)、ベースの太さ(80–120)、フロアタム、男性の声の最低音域 | ブーミー、輪郭が消える | 薄い・軽い | 近接効果で歌マイクが膨らむ。※150Hz未満は参考値 |
| lowmid | 150–300Hz | 低中域（ふくらみ） | 温かさ・厚み、溜まると「モワッ」 | 男性の声の基音(約100–200)、女性の声の基音(約165–260)、スネア胴鳴り、ギター/鍵盤の厚み | 濁る・こもる | 冷たく痩せる | **ウェッジのハウリング頻発帯** |
| boxy | 300–600Hz | こもり帯 | 箱の中の音、段ボール感 | タム、アコギ胴鳴り、声の「鼻づまり感」 | こもる・抜けない | 中身がスカスカ | 小さい会場・壁が近いと出やすい |
| mid | 600Hz–1.5kHz | 中域（芯） | 音の芯、電話の声、「ホンキー」 | ギターの芯、ボーカルの主成分、スネアの胴、ピアノ | ラジオ声・鼻にかかる | 引っ込む・遠い | 出る。削りすぎると歌が聞こえなくなる |
| presence | 1.5–4kHz | 中高域（明瞭度） | 言葉の聞き取りやすさ、**耳が最も敏感** | 子音、ギターのエッジ、キックのアタック、スネアのスナップ | 耳に刺さる・疲れる | こもる・言葉が聞き取れない | **最頻出の危険帯**（マイクの持ち上がり＋ウェッジのホーン） |
| sibilance | 4–8kHz | 高域（シャリ） | サ行、きらびやかさ | 歯擦音(サ行 5–8k)、ハイハット、シンバル、アコギのきらめき | サ行が痛い・シャリシャリ | 暗い・鈍い | 出ることがある（甲高い「ピー」） |
| air | 8–16kHz | 超高域（空気感） | 空気感、息のニュアンス | シンバルの余韻、息、倍音 | ヒスノイズ、耳障り | 鈍い・古い音 | 少ない（マイクの方向次第） |

> 数値は代表値。楽器・チューニング・奏者で変わるため、UI では「目安」と明記する。

### 2.2 音源（楽器・声）データ

各音源は「基音の範囲（実音）」と「倍音・特徴が出る範囲」を別々に持つ。周波数マップで2色の帯として描く。

| 音源 | 基音の範囲 | 特徴が出る範囲（例） |
|---|---|---|
| 男性ボーカル | 約85–400Hz（歌唱で上下） | 太さ100–200 / 明瞭度2–4k / サ行5–8k |
| 女性ボーカル | 約165–1kHz（歌唱で上下） | 温かさ200–300 / 明瞭度2–5k / サ行6–9k |
| エレキベース(4弦) | 41Hz(E1)–約400Hz | 太さ80–120 / 指・ピック音700–1k / 弦の擦れ2–4k |
| エレキギター | 82Hz(E2)–約1.3kHz | 厚み100–250 / 芯800–1.2k / エッジ2–4k |
| キック | 約50–100Hz | 胴60–80 / こもり300–500(削りどころ) / ビーター2–4k |
| スネア | 約150–250Hz | 胴150–250 / スナップ1–2k・5k |
| タム/フロアタム | 約80–250Hz | 胴 / アタック3–5k |
| ハイハット/シンバル | 約300Hz–（基音は曖昧） | 主成分3–16k |
| ピアノ | 27.5Hz(A0)–4.2kHz(C8) | 全域 |

基準: A4 = 440Hz。各帯域には「代表的な音名（例: 250Hz ≒ B3）」も表示し、楽器の弦/鍵盤と結びつける。

### 2.3 EQ と結びつけるデータ

- 31バンド GEQ の ISO 中心周波数（20, 25, 31.5, 40, 50, 63, 80, 100, 125, 160, 200, 250, 315, 400, 500, 630, 800, 1k, 1.25k, 1.6k, 2k, 2.5k, 3.15k, 4k, 5k, 6.3k, 8k, 10k, 12.5k, 16k, 20k）
- 検出した周波数 → 最寄りの GEQ フェーダー、パラメトリック EQ の提案値（例: 2.47kHz / Q≈8 / −3dB から）
- **「削ると何が犠牲になるか」**: 帯域と音源のデータから自動で文を作る
  例: 「250Hz を削ると、ハウリングは減りますが男性ボーカルの温かさとギターの厚みも減ります。細く（Q高め）、少しずつ削りましょう。」

### 2.4 データ形式

`src/kb/bands.ts`, `src/kb/sources.ts`, `src/kb/eq.ts` に型付きの定数として持つ（JSON でも可）。
文章は `src/content/*.md` に置き、帯域 ID から参照する。誤りを直したり監修を入れたりしやすくするため、**データと文章をコードから分ける**。

## 3. 機能設計

### 3.1 アナライザー（本番中に置いておく画面）

- 表示: スペクトル（対数周波数軸 50Hz–18kHz、1/3oct・1/6oct スムージング切替）とスペクトログラム
- FFT: AnalyserNode `fftSize=8192`（48kHz で約5.9Hz 刻み）。低域の分解能が必要な場面では 16384
- 「突出し続ける音」の強調: §3.2 と同じ検出器をリアルタイムで動かし、赤線と周波数ラベルで示す
- **学習の連動**
  - 背景に帯域の色帯（§2.1）を薄く描き、上部に呼び名（「こもり帯」など）を表示
  - グラフをタップ → その周波数の「周波数カード」
  - 楽器フィルタ: 「ボーカル」「ギター」…を選ぶと、その音源の範囲（§2.2）を重ねて表示

### 3.2 ハウリングチェック（最重要）

#### フロー（モニターチェック）

1. **準備ガイド**: iPhone を歌マイクの位置（スタンドにクリップなど）に置く。ウェッジの向きと音量を確認。音量注意の警告
2. **周囲音の測定（15秒）**: 帯域ごとの平均・ばらつきを保存（基準スペクトル）
3. **予想（学習モード）**: 「どこが危なそう？」を帯域ボタンから選ぶ（スキップ可）
4. **声を出す（20秒）**: 歌マイクに向かって発声。画面の文章を読み上げる、または「アー」でゆっくり音程を上下させる
5. **結果**
   - 危険な周波数を最大5件、危険度（注意/危険）つきで表示
   - それぞれに: Hz・音名・帯域の呼び名・最寄り GEQ・PEQ 提案・**周波数カードへのリンク**・**試聴ボタン（その周波数のサイン波を小音量で鳴らす）**
   - 予想との答え合わせ（当たり/近い/はずれ）
6. **保存**: 会場名・メモ・日時。前回結果との比較

#### 検出アルゴリズム

フィードバック検出で定番の特徴量（van Waterschoot & Moonen, "Fifty Years of Acoustic Feedback Control", 2011 に整理されているもの）を組み合わせる。

| 特徴量 | 意味 | ハウリングだと |
|---|---|---|
| PNPR（周囲帯域との比） | ピークが前後の帯域より何 dB 高いか | 鋭く突出する |
| PAPR（全体平均との比） | ピークが全体平均より何 dB 高いか | 大きい |
| 持続性（IPMP） | 連続フレームで同じビンにピークが残るか | 残り続ける |
| 増加傾向 | 時間とともにレベルが上がるか | 指数的に増える |
| 倍音の有無（PHPR） | ピークの整数倍にもピークがあるか | 正弦波的で倍音が少ない（声・楽器は倍音を持つ） |
| 基準との差 | 周囲音の測定値より何 dB 上か | 大きい |

- 各特徴量のしきい値を足し合わせてスコアにし、上位を出す。周波数は放物線補間で約1Hz 精度まで推定
- 150Hz 未満は「参考値（内蔵マイクでは不正確）」と表示する
- 単体テストは合成信号（ノイズ＋サイン波、声に見立てた倍音列）で行う。§6 を参照

#### 追加モード

- **リングアウト補助**: 「ゲインを少しずつ上げてください」→ 最初に鳴き始めた周波数を即座に検出・記録 →「そこを −3dB」→ 次へ。PA の現場の手順そのものを、画面の案内つきで練習できる
- **本番見張り**: アナライザー画面で常時検出し、増加傾向のあるピークが出たら画面を点滅させて周波数を大きく表示する

#### 学習の仕組み（アプリなしでできるようになるための段階）

| レベル | 表示 | ねらい |
|---|---|---|
| 1 補助輪 | 全部表示（Hz・帯域・EQ提案・解説） | 用語と手順を覚える |
| 2 ヒント | 帯域の呼び名だけ見せ、Hz と EQ 位置は自分で答える | 「こもり＝250〜500」を結びつける |
| 3 耳だけ | 先に耳で答え、アプリは答え合わせのみ | アプリなしで判断する |

- 正答率が一定を超えたら次のレベルを提案する
- 結果画面から「この周波数を聞き比べる」→ 周波数マップへ移動し、その帯域を中心に試聴

### 3.3 スピーカーチェック

- 客席から見て左 → 右 → 左右同時 → 逆位相の順にピンクノイズ（またはボイス）を再生
- 逆位相は「中央の定位が消えて、ぼやけて広がる」ことを、正相と交互に聞き比べて体験させる
- 解説: 逆位相が起きる原因（ケーブルの配線ミス、スピーカー端子の +/− の逆）と確かめ方
- 画面消灯は Wake Lock で防ぐ

### 3.4 学ぶ（学習コンテンツ）

1. **周波数マップ**（インタラクティブ）
   - 横軸は対数周波数（20Hz–20kHz）。帯域の色帯、楽器と声の範囲（基音／特徴音）、ピアノ鍵盤、31バンド GEQ を重ねる
   - どこでもタップすると、その周波数のサイン波または 1/3oct ピンクノイズが鳴り、カードが出る
   - 「自分の声」を登録すると、自分の基音と特徴帯域がマップ上に出る
2. **周波数カード**（§1 の共通部品）
3. **解説記事**（短く、図つき）
   - ハウリングはなぜ起きる？（ループゲインと位相、図解）
   - マイクの指向性とモニターの置き方（カーディオイド/スーパーカーディオイドの死角）
   - EQ の基本（削るが基本、Q の意味、GEQ と PEQ）
   - 耳を守る（音量・時間・耳栓）
4. **ミニクイズ**（フェーズ3の耳トレの前段階）
   - 知識クイズ: 「サ行がきついとき削るのは？」
   - 簡易な聞き当て: 3択の帯域当て（本格的な周波数当てはフェーズ3）
   - **出題を、自分のハウリング履歴に出た帯域へ寄せる**

### 3.5 声の登録（20秒の読み上げ）

- 長時間平均スペクトル（LTAS）と基音（YIN 法）を求める
- 「低音の膨らみ」「こもり」「刺さり」「サ行」の傾向を、帯域ごとのエネルギー比から判定する
- 結果を周波数マップと周波数カードに反映する（「あなたの声の基音は約130Hz＝低中域」など）

## 4. iPhone Safari の技術リスクと対策

**フェーズ1の最初に、実機での検証スパイク（1〜2日）を行う。** 以下は机上では確定できない。

| # | リスク | 影響 | 対策・検証内容 |
|---|---|---|---|
| R1 | マイク使用中は音の出力が受話口（耳に当てる側）に回る／小さくなる | 試聴・スピーカーチェックが聞こえない | 再生の前にマイクのストリームを止める。`navigator.audioSession.type`（Audio Session API）の効果を実機で確認 |
| R2 | 消音スイッチで Web Audio が鳴らない | 試聴が鳴らない | Audio Session API の `playback` 指定を検証。だめなら画面で案内する |
| R3 | エコー除去・ノイズ抑制・自動音量調整（AGC）が完全には切れない | ピークの検出が歪む | `echoCancellation/noiseSuppression/autoGainControl: false` の効き具合を、サイン波を鳴らして実測する |
| R4 | 内蔵マイクの低域特性 | 150Hz 未満が不正確 | 判定対象外にする（参考表示のみ） |
| R5 | AudioContext はユーザー操作がないと開始できない | 自動開始できない | 「開始」ボタンで resume。バックグラウンドからの復帰時も再開する |
| R6 | 画面ロックやアプリ切り替えでマイクが止まる | 測定が途中で切れる | Wake Lock。中断を検知したら「やり直し」を案内する |
| R7 | ホーム画面に追加していないと保存データが消されうる | 履歴が消える | PWA 化と `navigator.storage.persist()`。書き出し（JSON）を用意する |
| R8 | サンプルレートが端末で異なる（48kHz が基本） | Hz の計算がずれる | `audioContext.sampleRate` から計算し、固定値を使わない |

### 4.1 実機検証の結果（第1回: 2026-11-09 / iOS 18.7 Safari / ブラウザのタブで実行）

| # | 結果 | 判断 |
|---|---|---|
| R1 | **再現した。** マイク使用中は音が小さく／受話口から出る。Audio Session を `playback` にするとマイクが使えない（`InvalidStateError: AudioSession category is not compatible with audio capture`） | **マイクを使う場面と音を鳴らす場面を分ける**。測定中は鳴らさず、試聴やスピーカーチェックの前にはマイクを止める。マイクを止めると音量が戻るか、`play-and-record` で改善するかは第2回で確認 |
| R2 | 未確認 | 第2回で確認 |
| R3 | `echoCancellation: false` は適用された。`noiseSuppression` と `autoGainControl` は設定値に現れない。1kHz のピークは安定し、目立った自動補正の兆候はない | 実用上は問題なし。自動補正の有無は、別の機器から音を鳴らして第2回で確認 |
| R4 | 100Hz を検出できなかった。ただし **iPhone のスピーカー自体が 100Hz をほぼ出せない**ため、マイクの限界かどうか切り分けられていない | 別の機器（PC・ベースアンプなど）から鳴らして、第2回で確認 |
| R5/R6 | 非表示や画面ロックで AudioContext は `interrupted` になり、表示に戻ると自動で `running` に復帰。マイク（`mic=live`）は維持された。Wake Lock は効くが、非表示になると解放される | 状態 `interrupted` の扱いを実装に入れる（測定中なら「中断」として扱う）。表示に戻ったら Wake Lock を再取得する |
| R7 | タブでは `storage.persist()` が `false` | 想定どおり。ホーム画面に追加した状態（standalone）での結果を第2回で確認。保存データの書き出し機能は必須 |
| R8 | 48kHz、遅延は小さい（base 2.7ms / output 10ms） | 問題なし |

**フロー設計への反映**: ハウリングチェックの測定（周囲音・声）とアナライザーはマイクのみを使い、iPhone からは音を出さない。試聴・スピーカーチェック・周波数マップでの再生は、マイクを止めてから行う。2つのモードの切り替えをアプリ側で自動化し、使う人が意識しなくて済むようにする。

## 5. 技術構成

| 層 | 採用案 | 理由 |
|---|---|---|
| ビルド | Vite + TypeScript | 軽量、PWA プラグインあり |
| UI | Preact（または素の TS + Web Components） | iPhone で軽く動く |
| 描画 | Canvas 2D（スペクトル）／SVG（周波数マップ・図解） | 60fps の描画と、図の鮮明さ |
| 音声 | Web Audio API（AnalyserNode、重い処理は AudioWorklet） | 標準 API のみ |
| 解析 | 自前の小さな DSP モジュール（純関数で書きテスト可能に） | アルゴリズムを学習コンテンツで説明できるように中身を把握しておく |
| 保存 | IndexedDB（idb ライブラリ） | 履歴・声のプロファイル・学習進捗 |
| PWA | vite-plugin-pwa | オフライン対応・ホーム画面追加 |
| テスト | Vitest（DSP は合成信号で単体テスト）、Playwright（WebKit で UI の E2E。マイクは偽ストリーム） | 実機の音の確認は手動チェックリストで補う |
| 公開 | GitHub Pages または Cloudflare Pages（HTTPS） | 静的ホスティングで足りる |

### ディレクトリ案


## 6. 品質・テスト方針

- **DSP の単体テスト（TDD）**: 合成信号でテストする
  - 1kHz のサイン波 → 1kHz ±2Hz を検出する
  - 倍音列（声のモデル）に 2.5kHz の純音を足す → 2.5kHz だけを検出し、倍音は除外する
  - 時間とともに増加するピーク → 「増加傾向あり」
  - 周囲ノイズのみ → 何も検出しない
- **ナレッジベースの整合性テスト**: 帯域に隙間や重なりがない、全帯域に本文がある、参照している ID が存在する
- **実機チェックリスト**: §4 の R1〜R8 を iPhone 実機で確認する（バージョンの記録つき）
- **カバレッジ**: DSP・KB は 80% 以上

## 7. 一般公開に向けた配慮

- **聴覚の安全**: 試聴音は −20dBFS 以下で開始し、フェードインする。初回に音量の警告を出し、「大きいと感じたらすぐ下げる」を常に表示
- **免責**: 測定器ではないこと、dB は未校正であることを明記
- **プライバシー**: 音声は端末外に送らない。アクセス解析を入れる場合はクッキー不要のものに限る。プライバシーポリシーのページを用意
- **アクセシビリティ**: 色だけに頼らない（危険度にアイコンと文字を併記）、文字サイズの拡大に追従、片手で操作できるボタン配置
- **内容の正確さ**: 周波数の数値は「目安」と明記し、出典（音響の教科書・メーカー資料）をカードに載せる
- **ライセンス**: 試聴音源は自作か合成のみ（著作権のある音源は使わない）
